# 从图片制作运动路线图

使用本项目的本地编辑器。底图、轨迹和运动数据分别处理，导出时合成为 PNG。默认交付成品 PNG 和可重新导入的轨迹文件。如果为兼容或取景另存了底图，同时交付实际使用的底图副本。

## 根据图片决定画法

| 用户提供的图片 | 处理方式 |
| --- | --- |
| 有路线的地图、运动截图或手绘图 | 沿可见路线的中心描线，按箭头、起终点或用户描述确定顺序。遇到遮挡或分叉，保留可以确认的部分。 |
| 只有底图的街道地图、航拍图或操场照片 | 按用户给出的起终点、必经点或圈数走可辨认的道路和跑道。明确做展示时，可以选一条清楚的路径并标为示意。 |
| 普通照片、插画或无道路信息的图 | 把图片当作背景，在合适的留白处叠加用户提供的路线形状。用户要效果图且没给路线时，可画一条清晰的示意路线，避开主体。 |
| 图片与 GPX 一起上传 | 用 GPX 保留真实点序、距离和可用的时间数据。需要贴合图中的道路时，先确认它是同一地区，并用图上的已知位置配准。只有照片或缺少配准依据时，可以把图用作装饰背景。 |

用户要求还原实际运动，但路线或方向无法判断时，请用户标记起终点与关键转弯点，或提供 GPS 轨迹。用户只上传一张无路线的图并要求看效果时，可以直接制作示意图并标明。

## 从底图到导出

1. 按 [底图与取景](references/background-and-export.md) 确定一张最终底图。先处理方向和格式，再量尺寸、描点。用同一张图描线和导入。
2. 按真实行进顺序取点。在转弯、交叉口和起终点加点，缺失的路段分开储存。按 [路线数据格式](references/route-json.md) 用转换脚本生成 JSON。导入有时间戳的 GPX 可以直接走编辑器的 GPX 入口。
3. 使用用户给出的里程、可核实的单圈长度、比例尺或真实 GPS 数据。图片缺少标尺或已知里程时，里程留空。圈数和剩余段合计应与总里程一致。记录的配速按原顺序保留，生成的配速标为示意。
4. 在编辑器里先上传底图，再导入路线并点击「适配路线」。用缩放和拖动一起调整底图与轨迹。查看最终 PNG，确认轨迹贴合、路线清晰、起终点完整。绿色起点和红色终点使用同样大小的竖直图钉，尖端分别贴住首尾坐标。
5. 交付前说明路线来自描线、实测记录还是示意，并注明距离和配速的来源。未知的距离和配速留空。若截图模板显示默认示例数据，说明这些字段是示例值。
