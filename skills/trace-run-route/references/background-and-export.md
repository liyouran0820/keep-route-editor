# 底图、坐标与取景

## 准备底图

- 优先直接使用用户提供的清晰原图。地图保留道路形状、方向、比例尺和与路线有关的标签。照片与插画保留主体。底图保留为独立图片，路线和运动数字留在编辑器内编辑，由路线首尾生成图钉。
- 使用编辑器能解码的静态栅格图。图片打不开、有 EXIF 旋转、包含多帧或依赖外部图层时，先选定用户需要的画面并另存为方向正确的 PNG 或 JPEG。核对另存后的方向、长宽和画面内容，再用这份文件描点。保留原图。
- 图片本身带有标题栏、聊天边框或已有运动截图界面时，可先裁出有用的地图或照片区域。原图已经有明显轨迹时，以它作为描线参考。若新旧线条重叠影响辨认，优先使用同区域的干净底图。
- 默认保持宽高比。需要展示横幅、全景或特别窄的竖图时，优先保留整条路线。可等比例缩小、裁掉无关区域或以中性的纯色补边。缩放、裁切、补边和旋转一旦改变像素位置，就要按最终文件重新量点或变换坐标。
- 普通照片的路线放在空旷处，避开人脸和主要文字。地图没有显示的道路或建筑区域保持原图信息。必要的留白用纯色补足。

## 把路线对到图片

1. 读取实际上传给编辑器的文件的像素宽 `W` 和高 `H`。在 macOS 上可用 `sips -g pixelWidth -g pixelHeight <图片路径>` 读取已经定好方向的图。原点在左上角，向右为正 X，向下为正 Y。
2. 如果在缩略图上取点，先找显示的**图片内容**边界，扣除容器留白。实际图像在屏幕上的左上角为 `(L, T)`，显示宽高为 `(w, h)` 时，屏幕点 `(u, v)` 对应原图点 `((u-L) × W/w, (v-T) × H/h)`。
3. 用至少两个分散地标核对位置，例如入口与远端弯道。街道或跑道路线沿可通行部分的中心绘制。交叉口的行进顺序按已有证据确定。坐标和原图方向核对后才能按比例转换为 JSON。
4. GPX 在当前编辑器中会以 GPS 路线形状单独绘制。要和上传地图精确对齐，需要对应的地图像素和实地坐标。先用分散地标求变换，再用独立地标验证，最后输出该背景上的像素路线。如果只有场地名称、总里程或相似轮廓，可使用装饰背景，并说明它和 GPS 路线的关系。

## 用编辑器出图

1. 如果本地页面未运行，在项目根目录启动 `python3 -m http.server 8765 --bind 127.0.0.1`，用浏览器打开 `http://127.0.0.1:8765/`。已运行时可复用该页面。
2. 「自定义背景」上传准备好的图片。「可编辑轨迹」导入对应的路线 JSON 或 GPX，然后点「适配路线」。
3. 轨迹应完整落在原版界面上半部的地图区域。预览宽 360 像素，地图交互区高度 335 像素，标准 PNG 是 1080 × 2157。给竖直图钉的头部、地图按钮和重要地标留空间。优先保住整条路线及首尾，必要时再通过「底图缩放」和「移动底图」重新取景。
4. 检查原尺寸和缩略图。线路要有足够的粗细和对比度。深色航拍和图案复杂的照片尤其需要检查。若图片已有轨迹，检查新线与原线是否贴合。确认画面可读后点击「保存图片」导出。
5. 一并交付标准 PNG、可编辑的路线 JSON，以及实际使用的底图副本（如有）。用真实 GPX 直接作图时可保留原 GPX 作为可重导入的轨迹文件。
