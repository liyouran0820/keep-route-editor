# 路线输入格式

使用 [route_from_pixels.py](../scripts/route_from_pixels.py) 将像素描线转换为浏览器可导入的 JSON。运行命令时将脚本路径、输入文件和产物位置替换为当前任务的实际路径。

```sh
python3 skills/trace-run-route/scripts/route_from_pixels.py traced-pixels.json output.route.json
```

输入的 `imageWidth` 和 `imageHeight` 是最终底图像素尺寸。每段是至少两个 `[x, y]` 点，顺序与运动方向一致。脚本以原图宽高归一化坐标。不同段之间有实际断开、遮挡或缺失时，保留为独立段。文件里的第一点和最后一点分别是图钉的锚点。

## 示例 1 · 照片上的示意路线

在一张横幅照片的留白区画一条路线。原图没有比例尺或用时，输入可以只包含几何。若用户明确给了总里程，再加 `distanceMeters`。

```json
{
  "name": "照片路线示意",
  "imageWidth": 1600,
  "imageHeight": 900,
  "segments": [[[260, 730], [420, 635], [720, 645], [900, 555], [1290, 410]]]
}
```

## 示例 2 · 可按比例尺估算的地图路线

`reference` 支持 `scale-bar`（用直线标尺的两个端点）或 `known-segment`（沿长度已知的那段路取点）。估算距离等于路线像素长度除以标尺像素长度，再乘真实标尺米数。倾斜照片、不同缩放级别的拼图或变形手绘图通常无法用全图的单一比例尺。

```json
{
  "name": "河畔路线",
  "imageWidth": 1000,
  "imageHeight": 800,
  "segments": [[[240, 680], [240, 440], [560, 440]]],
  "reference": {"method": "scale-bar", "points": [[65, 745], [145, 745]], "meters": 100}
}
```

上例的路线长 560 像素，标尺长 80 像素，估算为 700 米。用户直接给出的总里程用 `distanceMeters`。旧版 `laps` 可用于把参考测得的单圈长度乘以圈数，适合核算，渲染多圈则使用下面的 `loop`。

## 示例 3 · 跑圈和分段配速

`loop` 要求一个闭合中心线、用户给出的总距，以及可信的单圈距离。中心线末点与首点相同。生成后的各圈可以有轻微偏移。前一圈的终点衔接后一圈的起点，最后一圈的终点可回到起跑附近。剩余小于一圈时沿同一方向截取剩下的距离。示意里程按中心线的单圈长度计算。

```json
{
  "name": "操场跑圈示意",
  "imageWidth": 800,
  "imageHeight": 600,
  "segments": [[[120, 300], [180, 170], [600, 170], [660, 300], [600, 430], [180, 430], [120, 300]]],
  "distanceMeters": 950,
  "loop": {"distanceMeters": 400, "driftPixels": 9},
  "pace": {"source": "simulated", "intervals": [[150, 375], [150, 363], [200, 355], [200, 352], [150, 345], [100, 338]]}
}
```

- 上例得到 2 个完整圈和 150 米。用场地资料前核对所画的是同一条跑道，标准田径场的单圈数值只适用于对应跑道。真实 GPS 圈迹直接保留。
- `driftPixels` 是原图像素单位的横移幅度。按照片或地图所示道路宽度选择小幅偏移。各圈应大体重叠，局部分开后再汇回。图钉使用输出路线的首尾点，两点相近时图钉也保持竖直。
- 每个配速区间是 `[距离米数, 每公里秒数]`。区间距离之和必须等于总距离，用时由各段距离和配速加权得出。`recorded` 用于用户提供的分段记录，`simulated` 用于示意，例如起步稍慢、中段趋稳、末段渐快。缺少配速数据而且没有示意需求时，省略 `pace`。
